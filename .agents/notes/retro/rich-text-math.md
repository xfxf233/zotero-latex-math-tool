# 复盘：混排功能

参见 [实现说明](../implemented/rich-text-math.md)。这里只留对以后有用的部分。

## 能带走的

1. **先读运行时源码，再动手。** tag 形状这类问题（阅读器里是 `{ name }`、存到条目是
   `{ tag }`、`fromJSON` 决定实际写入）在文档里查不到，只能啃 `app/omni.ja` 里的
   `annotations.js`。花在源码上的时间比在真机上反复试要少得多。
2. **纯逻辑先落成无依赖层。** `parse.ts` / `render.ts` 不碰 Zotero 和 DOM，单测可以直接
   跑；Zotero 集成层只做接线。后来改语法时，改动几乎都停在纯层里。
3. **兼容旧数据比新功能更容易出回归。** 所有既有标注都是纯公式和旧前缀，任何"顺手统一"
   重构都会伤到它们。评审新方案时，先把"旧数据走哪条路径"写进验收标准。
4. **几何类改动只能在真机上收敛。** 沙箱里没有字体、没有真实 viewport scale，
   缩放级别和基线问题全部是用户点出来的。涉及 rect 的改动，默认要经过多缩放级别验证。
5. **临时 UI 要排除出被观察文档。** 编辑器 iframe 一旦被纳入观察，每次打开都留一个
   observer 和一个 document 引用，泄漏得很慢但不会自愈。

## 判断下一次类似改动的快捷方式

- 问"这条标注在新旧代码里的识别结果是否一致"，比问"新功能好不好用"更能发现回归。
- 任何新的测量代码，先问"这里是什么坐标系、当前 scale 是多少"，再问公式对不对。
